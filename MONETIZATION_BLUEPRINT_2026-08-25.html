核心结论：中国大陆个人身份完全可以做付费订阅，但必须放弃 Stripe / ExtensionPay 路线（它们依赖 Stripe 商户号，标准地区不含中国大陆个人，需海外公司才能开）。正确路径是 MoR（Merchant of Record，名义商家）——平台当法律上的卖家，替你收全球卡、自动处理 VAT / 销售税、处理拒付退款，再把干净资金结算给你。你无需海外公司、无需自己报全球税。

1政策事实：Chrome Web Store 已无原生支付

起点不是写代码，而是确认政策边界——Google 在 2021 年后彻底移除了扩展内购能力。

  • CWS 原生支付（Chrome Web Store Payments）已于 2021-02-01 关停，没有「CWS 内置订阅」这回事。
  • 官方文档明确：新付费扩展必须改用第三方支付处理商，Google 不再替你管钱、管授权、管税务。
  • 这意味着：只要做付费，就得自建「支付 + 授权校验」这套栈——你自己对合规性负责。
  • 隐性陷阱：一旦订阅要邮箱 / 账号，CWS 当前的「零数据收集」申报必须改，否则复审会被打回。

对 PennyPilot 的利好：你当前审核中的版本是免费 + 零收集，正好是「最小外露面」基线。付费做成 v2 独立提交，不干扰本轮审核。

3推荐架构：Creem + Cloudflare Worker 校验链

你站点本就在 Cloudflare 上，Worker 当 entitlement（授权）校验后端正好，零额外基础设施。

① 扩展 popup点「Upgrade」→ openCheckout() 打开 Creem 结账页
→
② 用户付费Creem 收卡、处理 VAT / 拒付，回跳 success URL
→
③ WebhookCreem 通知 Worker（签名校验）
→
④ Worker校验后写 entitlement 到 KV / D1
→
⑤ 扩展启动查 Worker 拿状态 → 解锁高级功能

关键安全铁律

  • 永远服务端校验授权——客户端只「显示」解锁状态，绝不信本地 localStorage.isPremium（用户可改）。
  • Worker 用 Creem 签名校验 Webhook 真伪，再下发 entitlement；KV 存 {licenseKey, status, expiresAt}。
  • 隐私友好（契合「无账号」卖点）：走 Creem 的 License Key 模式——扩展本地只存 licenseKey，不碰邮箱；邮箱由 Creem（MoR）持有 → CWS「数据收集」申报仍可保持极简，只需在隐私政策注明「支付由 Creem 处理」。

Worker 校验伪代码（思路）

// Cloudflare Worker
export default {
  async fetch(req) {
    const url = new URL(req.url);
    if (url.pathname === '/entitlement') {
      const key = url.searchParams.get('license');
      const rec = await KV.get(key, { type: 'json' });
      // rec = { status:'active', expiresAt: 1710000000 }
      return Response.json(rec ?? { status:'none' });
    }
    if (url.pathname === '/webhook' && req.method === 'POST') {
      const sig = req.headers.get('creem-signature');
      if (!verify(sig, await req.text(), SECRET)) return new Response('bad',{status:401});
      const evt = await req.json();
      if (evt.event_type === 'checkout.completed') {
        await KV.put(evt.data.license_key, JSON.stringify({
          status: 'active', expiresAt: evt.data.subscription?.next_payment_at
        }));
      }
      return new Response('ok');
    }
  }
}

4Freemium 功能切分（保安装量优先）

原则：免费层保留核心卖点（州 / ZIP 预置提醒全免费），付费层只做「增强」，绝不砍掉免费核心——否则砍安装量、反噬 CWS 排名。

层级功能是否需账号
免费（核心）州 / ZIP 预置提醒全开（联邦税、州税截止、最低工资变动、Open Enrollment、FAFSA）；标准提前天数（如 ≤3 天通知）；最多 3 条自定义账单；单设备；桌面通知无账号
Premium（增强）无限自定义账单；更长提前提醒（14 / 30 天）；.ics 日历导出 / 可打印清单；多 ZIP / 多辖区切换（家庭、跨州）；高级布局 / 主题无账号
Premium v2（可选）多设备云同步（需 Creem 托管邮箱关联；属「做大之后」，不在本期）需邮箱

设计取舍：v1 付费层全部做成纯本地增强（无限账单 / 提前天数 / 导出 / 多 ZIP），不碰账号——彻底保持「无账号、无追踪」叙事，把隐私申报冲击压到最低。同步类作为 v2 再说。

5法律三件套 + 隐私申报变更

  • Terms of Service（服务条款）——CWS 要求付费须有 ToS 链接。
  • Refund Policy（退款政策）——CWS 硬性要求付费须有退款政策链接，否则拒绝上架。
  • 隐私政策（修订版）——在现有 allmoneycalc.com/pennypilot-privacy/privacy 基础上，新增一节「支付由 Creem 处理」：说明 Creem 作为 MoR 持有账单邮箱与卡信息，扩展本身仅存 license key。
  • CWS 数据收集申报变更——当前申报「零收集」。引入订阅后，若走 License Key（不存邮箱）仍可维持「极简 / 零敏感收集」；若 v2 加同步则需改申报 + 重填隐私权规范。本期 v1 维持零敏感收集叙事。
披露透明：商店长描述须写明「含可选订阅档（Premium）」与权益，不得隐瞒付费存在——隐瞒本身会引发差评 + 违反 CWS 披露要求。

6资金回境合规提醒（大陆个人）

  • Creem → 支付宝直接到账最顺；或经 Payoneer / 万里汇（WorldFirst）结汇到国内卡。
  • 个人每年 5 万美元外汇额度；经营收入建议注册个体户 / 公司并申报，避免大额走个人账户的冻卡 / 税务风险。
  • 起步小额（<$1k MRR）用 Creem + 支付宝即可，合规压力小；量级上去再规整主体。
  • MoR 已替你处理海外 VAT / 销售税，你无需自理全球税——这是 MoR 相对 Stripe 自建的最大省心点。

7执行步骤（过审后时序）

现在（审核中）：免费版保持「零收集」不动，不在审核中加付费，避免拖复审。

  1. CWS 审核通过、上线稳定（先跑通免费版真实安装 / 留存）。
  2. 注册 Creem，创建 PennyPilot 产品（订阅档 + License Key 模式），拿 API / Webhook 密钥。
  3. 部署 Cloudflare Worker 做 entitlement 校验后端（KV / D1 存状态）。
  4. 扩展接入：background 启动查 Worker；popup 加「Upgrade」按钮 → openCheckout()；按 entitlement 门控显示 Premium 卡片（之前为过审撤掉的卡片加回来）。
  5. 写 ToS / Refund Policy（托管于 allmoneycalc.com 子路径），修订隐私政策加「支付由 Creem 处理」一节。
  6. 商店长描述补「含可选 Premium 订阅」透明说明。
  7. 作为新版本（v2）提交 → CWS 复审（这次会审支付流程、披露、隐私申报）。
  8. 复审通过后，把落地页 index.html / cta.html 两处 TODO 商店 URL 替换成最终商品链接，重推 AllMoneyCalc。
